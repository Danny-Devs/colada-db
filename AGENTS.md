## Rules

- **CI is the gate of record** (ADR-021, `.github/workflows/ci.yml`). It runs on every push and PR: `gate` (the four commands below, on Node 20/22/24), `browser` (the L4 durability lane — real IndexedDB and real OPFS in a real Chromium, one Node because the variable under test is the browser; DAN-652), `publish-surface` (artifact invariants + the packed-manifest diff), `engines-floor` (the packed tarball installed and exercised on Node 18, the version `engines` claims — the toolchain itself needs ≥20.19, so these are two separate promises and the matrix tests them separately). **Do not weaken a gate to make CI green**; a CI-only failure is a finding. ✅ **CI is BLOCKING as of 2026-08-02** — the repo went public at the 0.1.0 publish, branch protection is on `main` with `enforce_admins: true`, and **six** checks are required (`gate (node 20|22|24)`, `browser durability lane`, `publish surface`, `engines floor (node 18 consumer)`). No one pushes directly to `main`, maintainer included; every change arrives by PR. Two traps that follow from that: **never use `[skip ci]`** — a skipped workflow leaves required contexts *pending* rather than absent, so the PR can never merge — and **any rename of a CI job must update the required-contexts list in the same PR**, because a required check that is never reported blocks `main` permanently. Read ADR-021 "Enforcement status" for the escape hatch and the rule that using it silently is the only misuse. Optional fast local mirror: `pnpm hooks:install` enables `.githooks/pre-push` (opt-in by design — a hook is bypassable with `--no-verify`, so CI stays the authority).
- **The publish surface is asserted, never printed.** THREE gates, each answering a different question: `pnpm check:publish-surface` (textual invariants over all four shipped artifacts, including the `./sqlite-worker` entry point), `pnpm check:api-report` (**ADR-022 line 2** — the emitted `.d.mts` surface diffed against the committed `etc/colada-db.api.md`; comments stripped so JSDoc edits don't churn it, everything else compared verbatim — regenerate with `node scripts/check-api-report.mjs --update` **in the same commit as the change that caused it**, because an unexplained update is the one thing it cannot catch), and `pnpm check:pack-manifest` (the packed file list diffed against `scripts/expected-pack-manifest.txt`, in **both** directions). Note `check-public-types.mjs` is NOT one of these — it asserts the types are framework-*free* (ADR-019), a question a surface can pass while having silently dropped an export. Adding or removing a published file is a deliberate act: edit the expected manifest in the same commit as the change that caused it, and say why. Both gates refuse to run over a missing, empty, or anchor-less artifact — an absence assertion over an empty file passes for the wrong reason.
- **Verify by running:** `CI=true pnpm -r test` + `pnpm -r typecheck` + `pnpm -r build` + `pnpm -r lint`, all green, before reporting done (workspace-recursive since 2026-07-20: the repo `.npmrc` sets `include-workspace-root=true`, so `-r` covers the core AND `packages/*`). Storage-engine changes additionally require observing real OPFS behavior in Chromium. Agent-surface changes additionally require the observe-run: `pnpm -r build && cd packages/mcp && pnpm observe`.
- **Workspace shape:** core engine at the root; edge packages under `packages/*` (ADR-008 §2 — core knows nothing about them). First member: `packages/mcp`, the read-only MCP agent surface (ADR-011, `docs/design/mcp-agent-surface.md`). Deny-by-default is structural there — never register a write tool on that surface; agent write affordances arrive only with the guard middleware, as their own deliberate surface.
- **Reading order:** this file → the Linear project (what's next) → `docs/adr/` (003–007 are the founding decisions; **022 = the irreversibility lines**) → `CHANGELOG.md` (last 3 entries) → `LESSONS.md` (skim for anything touching your area) → `TESTING-STRATEGY.md` if you are adding tests (L0–L6; L2 and L3 landed 2026-07-30, **L4 — the real-browser durability lane — landed 2026-07-31**; perf-regression pins are next). Storage-engine work belongs in L4: add it to `tests/browser/`, and assert `engine.persistent === true` before any survival claim — the SQLite worker falls back to an in-memory DB when OPFS is unavailable, so without that flag a green run can prove nothing durable.
- **ADRs are append-only.** 003–007 were adopted from the plugin repo at extraction; new engine decisions continue the numbering here.
- **No publish, no external pushes, no outreach** without Danny's explicit go. ⚠️ **This rule got MORE important on 2026-08-02, not less.** `colada-db@0.1.0` is published and the repo is public, so `"private": true` is gone and the guard rail with it. Every subsequent `npm publish` ships to real consumers and **a version on the registry cannot be un-shipped** — the same asymmetry ADR-022 is built around, now live rather than anticipated. Treat a version bump as the irreversible act it is: ADR-022's six lines are closed, so anything touching persisted format, the public API surface, the pack manifest, the entity-ref registry key, wire shapes, or the package name is now a **migration on someone else's disk**, not a design choice.
- **Shared knowledge base:** competitive/architecture research lives in the sweeos workspace at `core/projects/pinia-colada-normalizer-project/knowledge/` (steal-lists, landscape, routing). Read it before architectural work; file new findings back there.
- **`pnpm lint` is `oxlint --deny-warnings` PLUS a repo-local rule.** The flag is load-bearing: oxlint exits **0** on warnings, and with no `.oxlintrc.json` every default rule is warn-severity — so without it the only thing that could fail the Lint step was the repo-local rule below (measured 2026-07-23: `debugger` + an unused variable → two warnings, exit 0). Never drop `--deny-warnings` to get green; fix the warning, or set that rule's severity deliberately in `.oxlintrc.json`. `no-unguarded-process-env` (`scripts/no-unguarded-process-env.mjs`) bans any reference to the global `process` in shipped source (`.ts`/`.tsx`/`.mts`/`.cts`) unless DOMINATED by a `typeof process !== "undefined"` guard — shipped code must run in bundler-less runtimes (CDN / plain browser ESM) where `process` does not exist, and the failure only appears on degradation paths. It also catches `globalThis.process` / `self.process` / `window.process`, which fail identically with a `TypeError`. Accepted guard shapes include an inverted early return and a hoisted `const` (the repo's own house idioms), and there is an auditable escape hatch — `// lint-ok: no-unguarded-process-env — <reason>`, reason mandatory. Spec files are exempt. **The guard must spell the literal `process.env.NODE_ENV`, never `process.env?.NODE_ENV`** — optional chaining defeats the literal `define`/`replace` substitution bundlers key on, so the dev warnings leak into consumers' production bundles; `src/process-guard.spec.ts` pins this and no semantic test can. If the rule fires, read its message rather than reaching for an ignore: see LESSONS.md 2026-07-23.
- **`ENTITY_REF_MARKER` is a VERSIONED global registry key** (`Symbol.for("colada-db/entity-ref@1")`, ADR-020). Bump the `@N` suffix on any breaking change to the ref shape. All three branch sites — `encodeEntityRefs`, `decodeEntityRefs`, `isEntityRef` — must validate the SAME full shape (`entityType`/`id`/`key` all `string`); a global registry interns across copies and versions, so the marker alone is never sufficient.
- **The peer-range lesson:** before writing any dependency range, check whether the upstream publishes prerelease-only versions (`npm view <pkg> versions`) — `@sqlite.org/sqlite-wasm` must stay `"*"`. (Inherited from the plugin's LESSONS.md, encoded in `engines.spec.ts`.)
