## Rules

- **CI is the gate of record** (ADR-021, `.github/workflows/ci.yml`). It runs on every push and PR: `gate` (the four commands below, on Node 20/22/24), `publish-surface` (artifact invariants + the packed-manifest diff), `engines-floor` (the packed tarball installed and exercised on Node 18, the version `engines` claims — the toolchain itself needs ≥20.19, so these are two separate promises and the matrix tests them separately). **Do not weaken a gate to make CI green**; a CI-only failure is a finding. ⚠️ **CI is currently ADVISORY, not blocking** — the repo is private on a plan without branch protection (`gh api .../branches/main/protection` → 403), so a red run does not stop a merge. Read ADR-021 "Enforcement status" before treating a green tick as permission; do not use `[skip ci]` on anything touching `src/`, `scripts/`, or the workflow. Optional fast local mirror: `pnpm hooks:install` enables `.githooks/pre-push` (opt-in by design — a hook is bypassable with `--no-verify`, so CI stays the authority).
- **The publish surface is asserted, never printed.** `pnpm check:publish-surface` (textual invariants over all four shipped artifacts, including the `./sqlite-worker` entry point) and `pnpm check:pack-manifest` (the packed file list diffed against `scripts/expected-pack-manifest.txt`, in **both** directions). Adding or removing a published file is a deliberate act: edit the expected manifest in the same commit as the change that caused it, and say why. Both gates refuse to run over a missing, empty, or anchor-less artifact — an absence assertion over an empty file passes for the wrong reason.
- **Verify by running:** `CI=true pnpm -r test` + `pnpm -r typecheck` + `pnpm -r build` + `pnpm -r lint`, all green, before reporting done (workspace-recursive since 2026-07-20: the repo `.npmrc` sets `include-workspace-root=true`, so `-r` covers the core AND `packages/*`). Storage-engine changes additionally require observing real OPFS behavior in Chromium. Agent-surface changes additionally require the observe-run: `pnpm -r build && cd packages/mcp && pnpm observe`.
- **Workspace shape:** core engine at the root; edge packages under `packages/*` (ADR-008 §2 — core knows nothing about them). First member: `packages/mcp`, the read-only MCP agent surface (ADR-011, `docs/design/mcp-agent-surface.md`). Deny-by-default is structural there — never register a write tool on that surface; agent write affordances arrive only with the guard middleware, as their own deliberate surface.
- **Reading order:** this file → the Linear project (what's next) → `docs/adr/` (003–007 are the founding decisions; **022 = the irreversibility lines**) → `CHANGELOG.md` (last 3 entries) → `LESSONS.md` (skim for anything touching your area) → `TESTING-STRATEGY.md` if you are adding tests (L0–L6; L2 and L3 landed 2026-07-30, L4 is next).

- **Shared knowledge base:** competitive/architecture research lives in the sweeos workspace at `core/projects/pinia-colada-normalizer-project/knowledge/` (steal-lists, landscape, routing). Read it before architectural work; file new findings back there.
- **`pnpm lint` is `oxlint --deny-warnings` PLUS a repo-local rule.** The flag is load-bearing: oxlint exits **0** on warnings, and with no `.oxlintrc.json` every default rule is warn-severity — so without it the only thing that could fail the Lint step was the repo-local rule below (measured 2026-07-23: `debugger` + an unused variable → two warnings, exit 0). Never drop `--deny-warnings` to get green; fix the warning, or set that rule's severity deliberately in `.oxlintrc.json`. `no-unguarded-process-env` (`scripts/no-unguarded-process-env.mjs`) bans any reference to the global `process` in shipped source (`.ts`/`.tsx`/`.mts`/`.cts`) unless DOMINATED by a `typeof process !== "undefined"` guard — shipped code must run in bundler-less runtimes (CDN / plain browser ESM) where `process` does not exist, and the failure only appears on degradation paths. It also catches `globalThis.process` / `self.process` / `window.process`, which fail identically with a `TypeError`. Accepted guard shapes include an inverted early return and a hoisted `const` (the repo's own house idioms), and there is an auditable escape hatch — `// lint-ok: no-unguarded-process-env — <reason>`, reason mandatory. Spec files are exempt. **The guard must spell the literal `process.env.NODE_ENV`, never `process.env?.NODE_ENV`** — optional chaining defeats the literal `define`/`replace` substitution bundlers key on, so the dev warnings leak into consumers' production bundles; `src/process-guard.spec.ts` pins this and no semantic test can. If the rule fires, read its message rather than reaching for an ignore: see LESSONS.md 2026-07-23.
- **`ENTITY_REF_MARKER` is a VERSIONED global registry key** (`Symbol.for("colada-db/entity-ref@1")`, ADR-020). Bump the `@N` suffix on any breaking change to the ref shape. All three branch sites — `encodeEntityRefs`, `decodeEntityRefs`, `isEntityRef` — must validate the SAME full shape (`entityType`/`id`/`key` all `string`); a global registry interns across copies and versions, so the marker alone is never sufficient.
- **The peer-range lesson:** before writing any dependency range, check whether the upstream publishes prerelease-only versions (`npm view <pkg> versions`) — `@sqlite.org/sqlite-wasm` must stay `"*"`. (Inherited from the plugin's LESSONS.md, encoded in `engines.spec.ts`.)
